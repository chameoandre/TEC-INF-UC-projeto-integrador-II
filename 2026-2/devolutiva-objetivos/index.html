Arquitetura Metodológica

A Demanda: Do Problema Real à Submissão do Artigo

Os objetivos não são campos soltos de um formulário. Eles representam a linha do tempo executável que guiará o grupo da concepção aos testes práticos.

1
Problema Real
Dor real da comunidade ou estudantes identificada pela equipe.
2
4 Degraus Técnicos
Requisitos → Modelagem draw.io → Código Web → Validação.
3
Artigo Overleaf
Inserção dos objetivos no fechamento da Seção 1 (Introdução).
4
Execução & Git
Diagramas vivos, repositório GitHub e deploy no GitHub Pages.
5
Submissão COTB
Artigo científico concluído e submetido a evento oficial da SBC.
Por que isso importa?

Quando o avaliador da SBC lê seu artigo, ele avalia se a sua metodologia cumpriu exatamente o que foi prometido nos objetivos específicos.

Os 4 Degraus de Execução Técnica

A Trilha Obrigatória dos Objetivos Específicos

Todo projeto de PI-2 deve conter no mínimo 1 objetivo específico para cada um destes 4 degraus fundamentais:

DEGRAU 1
Requisitos & Diagnóstico
Mapear, Identificar, Levantar, Investigar
Entregável: Questionários, entrevistas ou levantamento documental das dores dos usuários.
DEGRAU 2
Modelagem & Design
Modelar, Prototipar, Projetar, Estruturar
Entregável: Diagrama de arquitetura no draw.io e wireframes visuais de navegação.
DEGRAU 3
Implementação & Código
Desenvolver, Codificar, Versionar, Publicar
Entregável: Aplicação web (HTML/CSS/JS) no GitHub com deploy público no GitHub Pages.
DEGRAU 4
Validação & Testes
Validar, Avaliar, Testar, Mensurar usabilidade
Entregável: Testes empíricos com usuários reais ou colegas de turma e métricas de satisfação.
REGRA ANTI-ESTUDO PASSIVO: Nunca coloque tarefas rotineiras ("estudar JavaScript", "ler artigos") ou papéis do professor ("ensinar finanças"). O objetivo de vocês é construir e validar a solução de software!
Análise Comparativa Real

Refatorando na Prática: Antes vs. Depois

Veja a diferença entre listar meras funcionalidades internas e estruturar os 4 degraus técnicos de engenharia:

Redação Típica Inicial (Problemas Comuns)
  • Falta de degraus de engenharia: "Disponibilizar conteúdos educativos sobre LIBRAS / Finanças / Leis" (Isso é conteúdo, não é entrega de software).
  • Foco no papel do professor: "Ensinar conceitos básicos de economia para jovens" (O software apoia, mas quem ensina é o usuário).
  • Repetição do Geral: O 1º específico apenas repete com outras palavras o que já estava dito no Objetivo Geral.
  • Omissão completa da modelagem e validação: Não cita draw.io, wireframes, nem testes de usabilidade com a turma.
Redação Padrão COTB/SBC (Refatorada)
  • Degrau 1 (Requisitos): "Mapear as necessidades e dificuldades de aprendizagem através de questionário com o público-alvo;"
  • Degrau 2 (Modelagem): "Modelar a arquitetura no draw.io e prototipar wireframes responsivos de interação;"
  • Degrau 3 (Código): "Desenvolver a plataforma web (HTML5, CSS3, JavaScript) versionada no GitHub com deploy no GitHub Pages;"
  • Degrau 4 (Validação): "Validar a usabilidade e interatividade aplicando testes práticos com estudantes e coletando métricas."

Para tanto, definem-se os seguintes objetivos específicos:

  \item \textbf{Validação:} Validar a usabilidade da solução 
        através de testes práticos com a turma.
\end{enumerate}

1. Introdução

A utilização de ferramentas digitais no ensino técnico representa uma oportunidade essencial para a resolução de problemas práticos cotidianos. Entretanto, a falta de ferramentas acessíveis ainda dificulta...

O objetivo geral deste trabalho é desenvolver uma plataforma web interativa voltada ao apoio à aprendizagem acessível. Para tanto, definem-se os seguintes objetivos específicos:

  1. Requisitos: Mapear as principais necessidades dos usuários mediante aplicação de questionário;
  2. Modelagem: Modelar a arquitetura no draw.io e prototipar os wireframes das interfaces;
  3. Implementação: Desenvolver a aplicação web utilizando HTML5, CSS3, JavaScript e versionamento Git;
  4. Validação: Validar a usabilidade da solução através de testes práticos com a turma.
